# optokbd v0.2.0 設計メモ

XIAO nRF52840 + ZMK の左右分割ワイヤレスキーボード（片手 25 キー、7 列、MX ホットスワップ、ガスケットマウント）。
ケースは build123d、基板は KiCad 10 で設計している。2026-11-13 に左手を組み上げて動作を確かめた。右手はこれから。

- 寸法の値はコード（`case/`）が正。このメモは、決めたことの理由と、コードからは読み取りにくい情報をまとめる
- 2026-10-11〜10-31 の作業の引き継ぎメモ（`docs/handoff-*.md`）は、このメモにまとめて削除した。経緯を追うときは
  git の履歴（`git log -- docs/`）から読める

## 座標系と高さ

- 平面の座標は**プレート DXF（`plate/plate_left.dxf`）のまま**（mm、y は奥が正、原点はキー配置の原点）
- ケースの平面形はすべて、プレートの外形（タブを除く）を辺ごとにオフセットして作る（`layout.py`）。辺は 2 種類:
  `edge`（奥と手前。ボトムケースに壁がある）と `side`（左右と右下の斜め。ボトムケースに壁がない）
- 高さはボトムケースの z（底面の基準が 0）とトップケースの z（下端が 0）の 2 つ。**ボトムケースの z = トップケースの z +
  `L.Z_OFFSET`（7.0）**
- 底蓋まわりは、底蓋の外面を基準にした座標系 `bay.FRAME`（x はそのまま、v は底蓋に沿って奥へ、w は底蓋に垂直に上へ）でも作る

| 高さ（ボトムケースの z） | |
|---|---|
| トップケースの上面 | 29.6 |
| プレート | 22.5〜24.1 |
| ボトムケースの壁の上端（ガスケットを受ける面） | 20.1 |
| マトリクス基板 | 17.5〜19.1（MX の規格でプレートの上面から 5.0 下） |
| ボトムケースの床の上面 | 14.5 |
| 奥の面取りの上端 | 14.0 |

- すき間: プレートと基板 3.4（3 mm のフォーム）、基板と床 3.0（2 mm のフォーム。ふだんは基板に触れず、基板が大きくたわんだ
  ときだけ受け止める）
- 底面のチルト 6.25°。手前の床の厚さ 2.0

## ケース

### 方針

- **ネジは M2 の六角穴付きボルト + ナットで統一**。インサートは使わない（入れる余地を作るとトップケースの外形が奥と手前で 1 mm
  広がり、ベゼルが太くなる）
- **縦の角（Z 方向の稜線）とネジ頭の穴の縁は R のまま**。面取りにすると、印刷で角が膨らんだ
- エレファントフット対策の 45° の面取り（0.3〜0.4）は、**印刷でベッドかサポートに当たる面の縁（水平な稜線）だけ**に入れる
- 面取りとフィレットは、**面取りを R より先にかける**（R が辺を接線でつなぐと、OCC の面取りが外周全体に回る）

### トップケース（`top.py`）

- ベゼル 5.0 mm。キーの開口は 1U の枠から片側 0.6（18 mm のキーキャップとは 1.125 mm）。上面の外周の面取り 3.0
- 外壁は内側へ厚くして、ボトムケースとのすき間を 0.25（`L.TOP_FIT`）に詰めてある。左右と斜めの辺の内面はプレートから 0.6
  （`L.TOP_SIDE_GAP`。かぶせるときに、外へ出たマトリクス基板とプレートのフォームのそばを通る）
- 下端はボトムケースの傾いた底面から 1.5（`L.REVEAL`）上げてあり、横から見るとボトムケースが帯状に見える
- ナットのポケット: 二面幅 4.2、厚さ 1.6（1.8 では傾けるだけでナットが抜けた。きつさは厚さで決める）。上面を下にして刷るので
  ポケットの天井が印刷の天井になる。サポートなしの段付きブリッジ（`NUT_CEILING = "stepped"`）
- 印刷: 上面を下にして、Y 軸まわりに 180° 回す（キーボードの奥がプリンタの奥）。シームは奥の角の R1 にペイントする
  （スカーフシームは使わない。平らな奥の面に 10 mm ほど広がって目立つ）

### ボトムケース（`bottom.py`）

- 壁の上端は全周平ら（20.1）で、ガスケットを受け、トップケースの段差に当たる。2026-11 に、キーを押し込んだとき基板が床に
  当たりやすかったので 0.5 上げた（トップケースは `Z_OFFSET` で同じだけ上がり、机からの高さは変わらない）
- 奥の面取り 14 × 6。断面は円弧で中央を 0.2 外へふくらませる（`BEVEL_BULGE`。印刷すると内側へ反ったのを打ち消す）
- ケースのネジ 6 本: 奥の 3 本は座面 16.3、手前の 3 本は 16.4 に上げ、ネジ頭をトップケースの壁の裏に隠す。床の上にネジ頭の穴を
  囲む台がある（マトリクス基板の奥の辺には、奥の台を避ける切り欠きがある）
- 手前の 3 本のネジ頭の穴は外面より外へはみ出すので、トップケースの下に見える帯（`L.REVEAL`）に、ネジごとに幅 3.7 × 高さ 1.5 の
  切り欠きが見える。ネジの位置を変えない限り避けられない
- 印刷: 傾いた底面を下にする。底蓋が当たる四隅のボスの下面はサポートの上に刷る（下の「印刷」）

### 重り（`bay.py` の `WEIGHT*`）

- 収納部の左右の、底面と床の上面の間に、重りを 2 × 2 個ずつ入れる穴がある。穴は底面に平行で、11 mm の辺を左右、19 mm の辺を
  奥行きに向ける。穴の底は底面から 1.4（奥のゴム足の目印の溝の下に 1.0 残す）、穴のまわりの肉は 1.0 以上（`bottom.py` の
  `check_weights` で確かめる）
- 穴は床の上面まで抜いてあり、上から重りを入れる（天井を作ると、印刷の向きで幅 22 mm の水平なブリッジになる）。上は別の部品の
  蓋（`weight_lid()`）でふさいで接着する。蓋は収納部の天井と同じく、ボトムケースの受けの段に載る: 重りの上 0.3 の高さで、穴を
  奥と手前へ 1.0 広げてある。蓋の上面は床の上面と同じ高さ。いちばん薄い所（手前の端）は約 1.1
- 穴は外の壁を厚くするために収納部の側へ寄せてあり、収納部の天井の受けの段の縁に接する（天井の下面より上では、蓋の入る所と
  受けの段がつながる。その下は受けの段の下の幅 1.5 が、穴と収納部の間の壁）。外の側面までの壁は、左の穴で約 2.0、右の穴で
  約 3.5
- 左右には受けを作れない: 左の穴の外の壁は薄く、収納部の側は天井の受けに接している。左の穴の幅（外の側面と天井の受けの間）が
  足りないので、重りと穴のすき間は片側 0.1
- 4 つの穴（左右の手の、収納部の左右）は平面形と高さが同じなので、蓋は 1 種類（`out/print/weight-lid.*`）を 4 つ刷る
- 右の重りは XIAO の端から約 15 mm。組んだ後に BLE の通信距離が落ちていないか確かめる

### 底蓋と収納部（`bay.py`）

- 底蓋はボトムケースの底面と面一の平らな板。コントローラー基板と電池は底蓋に平行に載る
- **閉め方**: 手前を下げて傾け、XIAO の USB-C を奥の壁の穴に差し込み、奥の端を支点に手前を持ち上げて閉じる。四隅を M2 × 5 で、
  ボスに横から差したナットに留める。まっすぐ押し込むと USB-C が壁に当たる
- やめた方式: しなるラッチ（印刷で精度が出ない）、手前のツメを軸に回す（ツメが抜けかけた状態で回り始めて USB-C が奥の壁に
  当たる）、奥の中央 1 本のネジ（奥の角が浮く）
- ボスのナットの溝: 幅 3.95、厚さ 1.6、45° の切妻屋根（サポートなし）、口に案内のテーパー
- **収納部の天井は別の部品**（`ceiling()`）。ボトムケースの受けの段に上から載せて接着する。一体にすると印刷の向きで水平な広い
  張り出しになり、その層で外形がゆがんで奥の面取りに筋が出た。天井は 2 枚に分かれる
- J1 のケーブルの溝: 収納部の手前の壁から手前へ。50 mm のケーブルの余りを手前の広い所（幅 23.5、奥行き 14）に横へ輪にして収める。
  広い所は左だけに広げ、右の壁は収納部の中の溝と天井の開口の右の端にそろえる（その右の天井は受けの段に載る）。
  手前の端に、浮いたケーブルを押さえる張り出し（`J1_LIP`）。溝の下の壁の角は 45° の斜面で、閉じるときに垂れたケーブルを
  溝へ押し上げる。天井は溝の上には作らない
- 電池のリード線は、底蓋のキノコ形の柱 2 本に巻いて J2 / J3 へ
- 印刷: 底蓋は外面を下、天井と重りの穴の蓋は下面を下

### パームレスト（`palmrest.py`）

- 断面を左右へ押し出した形。奥の面はキーボードの手前の面（6.25° 手前へ傾く）と平行で、すき間 1.5
- 印刷: 左の端の面を下にして立てる。ブリムを付ける

### はんだ付けの治具（`jig.py`）

- 表向きの台（`solder-jig-top`）: 部品の面を上にしてコントローラー基板を載せ、J1 と XIAO をはんだ付けする。取り付け穴 H1〜H4 に
  ピンを通して位置を決め、カプトンテープで押さえる。XIAO の USB-C は奥の壁の上の開いた溝に落とし込む（長円の穴に通すと、
  はんだ付けした後に抜けなかった）
- 裏返しの台（`solder-jig-flip`）: 部品の面を下にして載せ、XIAO の電池の穴（VBAT、GND）と J2 / J3 をはんだ付けする。J2 / J3 の本体の
  下の受けの段は、KiCad の 3D モデルの高さでは高すぎ、段なしでは J2 が浮いたので、その半分ほどの高さにしてある

## 印刷

- プリセット（`print/bambu/`）: プロセスは 0.2 mm ノズル・層 0.1 の High Quality をもとにした `optokbd top`（インフィル 100%）と
  `optokbd bottom`（インフィル 27%、壁 6 周、サポートあり）、フィラメントは `Bambu PLA Matte 0.2 nozzle - optokbd`。Bambu Studio で
  変えたら `python3 scripts/sync_bambu_presets.py` でリポジトリに写してコミットする
- サポートの上に刷る面（ボトムケースの、底蓋が当たる四隅のボスの下面）: 接触面の層だけ Bambu の PLA 用サポート材、上の Z 距離 0。
  サポートの上の 1 層目は縁が垂れるので、壁につながらない縁はモデルで面取りしてある
- エレファントフットはモデルの面取りで打ち消しているので、スライサーのエレファントフット補正は標準のままにする
- トップケースのナットのポケットの段付きブリッジは、1 段 0.2（`top.NUT_LAYER`）で作ってある。層の厚さを変えるときは
  `NUT_Z[0]` が上面から層の厚さの整数倍の位置にあること（`_on_layer` の assert）

## 組み立てのメモ

- ガスケットはタブ 1 つにつき上下 2 枚。上下とも、シールの面をタブに向けて貼る。下のガスケットはカットデータでは鏡像になって
  いるので、裏返して貼る
- 重りは、剥離紙をはがして重りの穴の底に貼る（左右 2 × 2 個ずつ）。重りの穴の蓋（片手 2 つ）と収納部の天井（2 枚）は、
  ボトムケースの受けの段に上から載せて接着する
- ケーブルの向き（同方向 / 逆方向）でピン 1 がどちらにつながるかが変わるので、新しいケーブルはテスターで導通を確かめてから使う

## 基板

### スイッチプレート（`plate.py`、`pcbs/plate`）

- 左手の DXF（`plate/plate_left.dxf`。外形、タブ、スイッチ穴）から作る。**右手は同じ板を裏返して使う**。
  `plate/plate_right.dxf` は外形とタブのない古いもので、使っていない
- タブ 4 つ（幅 26.05）。Edge.Cuts の線は 0.15 mm（0.05 では JLCPCB のプレビューで穴の辺が消えて見えた）

### マトリクス基板（`pcbs/matrix-left`、`pcbs/matrix-right`）

- 部品（裏面）: Kailh MX ホットスワップソケット、ダイオード 1N4148W（SOD-123）、J1 = SM11B-SRSS-TB（参照番号は J4）
- 配置は `scripts/place_matrix.py`。R1〜R3 のキーは上下を反転。ダイオードはソケットのパッド 2 の真下。右手はキーの位置と回転を
  x で反転するが、フットプリントは鏡像にしない
- 外形は `matrix_mock.py` が書き出す（奥と手前はプレートの 0.75 内、左右と斜めは 0.3 外）
- KiCad の座標とプレートの座標: 左手は x = X − 50、y = 50 − Y（KiCad の Y は下が正）。右手は原点が (185, 50) で x を反転。
  J1（J4）は R0C4 と R1C4 の境目（プレートの座標で (85.73, −20.955)）、差し込み口は手前（コントローラーの側）
- DRC で回路図との照合の `net_conflict` が 50 件ほど出るが誤検出（ネットリストと全パッドのネットが一致することを確かめた）
- J1 のピンの割り当て（ピン 11 → 1）:
  - 左手: C3 C2 C1 C0 R3 R2 R1 R0 C4 C6 C5
  - 右手: C5 C6 R3 R2 R1 R0 C4 C0 C1 C2 C3
- ダイオードはカソードが行の側（col2row）

### コントローラー基板（`pcbs/controller`、左右共通）

- 外形は `bay.py` が書き出す（基板の座標の原点は奥の辺の直線部分の中央。KiCad の (100, 90) に置いてある）
- J1 のピン 1〜11 = XIAO の D6 D5 D4 D3 D2 D1 D0 D10 D9 D8 D7
- 電池は J2（左手）/ J3（右手）。ピン 1 が GND、ピン 2 が VBAT（シルクの − / +）。実物の電池の極性と合うことを確かめてある
- 取り付け穴 H1〜H4 は回路図に記号のない基板だけの部品。「回路図から PCB を更新」（F8）で消さないように注意する
- GND のベタはなし（XIAO のアンテナのため）

### JLCPCB への発注

- ファイルは `scripts/export_gerbers.py` と `scripts/export_jlc_assembly.py` で `pcbs/<基板>/jlcpcb/` に書き出す
- 基板: FR-4 TG135、2 層、ビア処理「レジストカバー」、マーク除去
- 部品実装（マトリクス基板）: Economic、裏面。ソケット C41430893（HanElectricity。Kailh のものは在庫がなかった）、
  ダイオード C81598、J1 C515956。CPL の回転は、裏の部品は `180 − KiCad の向き`。ソケットはフットプリントが表でパッドが裏なので
  Bottom として扱い、中心はパッドの範囲の中心
- 部品の向きは、EasyEDA のフットプリント（`https://easyeda.com/api/products/<LCSC 番号>/components?version=6.4.19.5`）の
  パッドと穴を重ねて確かめられる。プレビューと実際の実装の向きが食い違った報告があるので、「Confirm Production File」をオンにする

## フォームとガスケット（`foam.py`）

- 遊舎工房「レーザー加工サービス（その2）」の PORON。デザインルール: https://yushakobo.jp/lasercut/
- テンプレート `Laser_Poron_template.svg` は遊舎工房のファイルなのでリポジトリに入れない。デザインルールのページのリンクから
  入手して `case/vendor/` に置く（加工の仕方は `foam.py` の先頭）
- 床のフォーム（2 mm）: ソケット、ダイオード、J4、スイッチの軸、収納部の天井の開口、床から出ている台を切り抜く。右手の基板は
  ダイオードのオフセットを反転していないので、右手は右手の基板から作る（左の鏡像ではない）
- プレートのフォーム（3 mm）: 14 mm 角の穴。左右共用（右手には裏返す）
- ガスケット（3 mm、接着シート付き）: タブ 1 つにつき上下 2 枚、プレートと合わせて 6.5 に挟んで約 18% つぶれる。
  内側の辺がプレートから +0.8 の推奨案と、+0.7 の上限案（シートの右半分、目印の丸つき）の 2 案を作り、**上限案で問題なかった**

## ファームウェア（ZMK）

- 設定は [hhiroshell/zmk-config](https://github.com/hhiroshell/zmk-config)。GitHub Actions でビルドしたファームウェアを書き込む
- ピンの対応は、上の J1 の割り当てとケーブルの向きで決まる。マトリクス基板のピン k がコントローラーのピン 12 − k につながる
  ケーブルなら、XIAO のピンは次のとおり（逆なら作り直す。基板は変えなくてよい。正しい対応は zmk-config の設定）:

  | | C0〜C6 | R0〜R3 |
  |---|---|---|
  | 左手 | D3 D4 D5 D6 D9 D7 D8 | D10 D0 D1 D2 |
  | 右手 | D10 D9 D8 D7 D0 D6 D5 | D1 D2 D3 D4 |

- 右手の C0 は外側（小指の側）。KLE の並び（右手は内側が列 0）とは matrix-transform で合わせる

## 右手に向けて

- `case/` のケースのスクリプトは左手の形を作り、右手は左右に反転して `-r` として書き出す（`layout.right_hand()`。反転の面は
  ケースの左右の中央）。右手のマトリクス基板は、キー・J1・外形が左手の鏡像の配置になっていることを確かめてある
- プレートとコントローラー基板は左右共通。マトリクス基板とフォームは右手専用のものがある（上記）
- 右手のコントローラー基板は、電池を J3 に挿す。底蓋を反転すると、電池のケーブルのガイドは基板の右の切り欠きと J3 に合う

## 作業のメモ

### ケースのコード

- `./build.sh`（`case/`）で `out/` を消してすべて作り直す。1 つだけなら `uv run python <スクリプト>.py`。`--show` で
  OCP CAD Viewer に表示する
- `bay` と `matrix_mock` は互いを使う（`bay.floor_openings()` は関数の中で `matrix_mock` を、`matrix_mock` は `__main__` の中で
  `bay` を読み込む。先頭で読み込むと循環する）
- 寸法の決まりはモジュールの先頭の `assert` で確かめている。探るときは `python -O` で外せる
- プレビュー: OCP CAD Viewer のスタンドアロン版（`ocp-viewer --port 3939`、http://127.0.0.1:3939）を開いてから `--show` で送る。
  開く前に送ったモデルは届かない。ビューアは物体の名前ごとに表示・非表示を覚えているので、前に隠した名前で送ると表示されない
- Claude Code のサンドボックスの中では `uv run` が `~/.cache/uv` に書けずに止まる。`UV_CACHE_DIR` を `$TMPDIR` の下に向けるか、
  `.venv/bin/python` で実行する

### KiCad

- 基板を変えるスクリプトは、PCB エディタの「ツール → スクリプトコンソール」で 1 行で実行する（コンソールは 1 回に 1 つの文しか
  受け付けない）: `exec(open('<リポジトリ>/scripts/<名前>.py').read())`
- 開いている基板のファイルを直接書き換えない。スクリプトは先に基板のコピーに当てて確かめる（システムの `/usr/bin/python3` で
  `pcbnew.LoadBoard`、`kicad-cli pcb drc`）。回路図を書き換えるときは、ロックファイルがないことを確かめる
- 配線を変えたら B キー（ゾーンの塗り直し）を押してから保存する。古い塗りのままだと、DRC がティアドロップのクリアランス違反を
  見逃す
- KiCad 10 の裏面のフットプリントは「上下反転 + 回転」として持たれる。表の向きを左右に裏返した形にするには角度を `r + 180` にする
- 円弧の配線で始点と終点がほぼ重なったもの（ドラッグで直したときにできる）は、DRC でほぼ一周の円として扱われる
- `kicad-cli pcb drc --refill-zones` でゾーンを塗り直してから DRC できる。`kicad-cli pcb export drill` の座標は y が上向きで、
  `--drill-origin plot` で補助原点の基準になる
- コントローラー基板の座標 (x, y) は、KiCad のプロパティの画面（ページの絶対座標）では (100 + x, 90 − y)
- KiCad で開いているファイルがあるときは `git stash` を使わない（開いているファイルも一時的に書き換わる）
- pcbnew の Python: 部品を順に処理しながら `board.Remove()` すると SWIG のエラーになることがある。消すものを先に集めてから消す
- KiCad の SVG には検索用の見えない `<text>` が入っていて、ImageMagick で PNG にすると文字が二重に見える。先に消す。
  日本語の入った SVG は `font-family="Noto Sans CJK JP"` を指定しないと文字が抜ける

### OCC / build123d のハマりどころ

- 時計回りの輪郭の Face は法線が下を向き、`extrude` が下へ伸びる。`dir=(0, 0, 1)` で向きを固定する（shapely の輪郭は
  `orient(poly, 1.0)` でそろえる）
- ほぼ接する形の組み合わせで微小な面や切れ端ができ、ブーリアンが黙って何もしなくなる。頂点は辺の交点から計算する
- 押し出し用の断面の折れ目が外面にちょうど接すると、長さ 0 の辺ができて 3MF のメッシュが壊れる。折れ目は外面の外に置く
- OCC の面取りは、壁が薄い所を越える大きさでは作れない。1 辺ずつ大きさを変えて試すと切り分けられる
- 2D の `offset` は、ずらした輪郭が複数に分かれると失敗する。レーザー用の 2D は shapely（`buffer`、`unary_union`）で作る
- 円弧の断面を回転させた面は `GeomType.TORUS`（円すいではない）
- 3D プリンタは高さ方向を層の厚さ単位でしか刷れない。細かいきつさの調整は横方向で行う
