## 環境と作業の流れ

- ケースの Python プロジェクトは `case/`（uv、build123d 0.13.0）。出力は `case/out/`（`.gitignore` 済み）

  ```bash
  cd case
  uv run python top.py                    # トップケース、トップケースのナットのテストピース（top-nut-test-l）
  uv run python bottom.py                 # ボトムケース（収納部の加工、ゴム足の目印込み）
  uv run python bay.py [--show]           # 底蓋、テストピース（ネジまわり・ナットの溝・収納部）、コントローラー基板の外形
  uv run python gasket.py                 # ガスケット 8 枚（印刷用の配置）
  uv run python plate.py                  # プレートのモック（DXF から）
  uv run python matrix_mock.py [--show]   # マトリクス基板のモック、スイッチの穴のテストピース、マトリクス基板の外形。kicad-cli が必要
  uv run python controller_test_board.py  # 印刷用の仮コントローラー基板と XIAO のモック。kicad-cli が必要
  ```

- プレビュー: OCP のスタンドアロンビューア（http://127.0.0.1:3939）を内蔵ブラウザで開いてから送る。ビューアは物体の名前ごとに
  表示・非表示を覚えているので、送るたびに名前を変える（`-v15` まで使った）。ツールバーやツリーの目のアイコンを誤ってクリックすると
  表示が消えるので、困ったら名前を変えて送り直す
- 全パーツのプレビュー: トップとボトムケースを半透明（alpha 0.25 / 0.3）にし、底蓋、プレート（`plate.mock()`）、ガスケット、
  マトリクス基板のモックと J1、コントローラー基板・XIAO・USB-C・電池（`bay.dummies()`）をまとめて送る
- **Remote Control がオン**: ユーザーはモバイルからも見ている。モデルを変えたら、ビューアに加えて SVG（`project_to_viewport` +
  `ExportSVG`）を `SendUserFile` で送る。基板の図は `kicad-cli pcb export svg` を `convert -density 500` で PNG にして送る
- KiCad 10.0.6。基板はユーザーが KiCad で開いていることが多いので、ファイルを直接書き換えず、スクリプトをスクリプトコンソールで
  実行してもらう。実行前に基板のコピーに当てて確かめる（システムの `/usr/bin/python3` で `pcbnew.LoadBoard` し、
  `pcbnew.GetBoard` と `pcbnew.Refresh` を差し替えて `exec`、`kicad-cli pcb drc` で確認）
  - `scripts/place_matrix.py`: マトリクス基板のスイッチ・ダイオード・J1 の配置
  - `scripts/set_edge_cuts.py`: Edge.Cuts を `case/out/*.json` の外形で描き直す（基板のファイル名でコントローラーかマトリクスかを選ぶ）
  - `scripts/add_silk_labels.py`: コントローラー基板の裏のシルク（電池の極性、名前と版）
- ユーザーは手で配線や修正をして、保存してから「チェックして」と頼むことが多い。基板のコピーで DRC を流し、HEAD との差分
  （配線の端点の一覧の差など）を見て報告する
- ユーザーとのやりとりの約束（メモリにも保存済み）: 回答は日本語。モデルを更新したら内蔵ブラウザのビューアに表示する。
  コミットメッセージは英語、コミットや push は頼まれたときだけ。ネジは M2 の六角穴付きボルト + ナット（インサートは使わない）。
  コミットは内容ごとに分ける（1 つのファイルに複数の変更が混ざるときは、内容ごとの中間の版を作り、作業用の worktree でそれぞれから
  部品が作れることを確かめてから `git update-index --cacheinfo` で入れる）

- ゴム足: Ø7.9 × 2.2 のクッションゴム。底面に Ø6.0（幅 0.6、深さ 0.4）の円の溝の目印（`FOOT_POS`、底面の座標）。座ぐりは

### トップケース（`top.py`）

- ベゼル 5.0 mm（`HEIGHT` 22.6、`CAVITY_TOP` 17.6）。上面を下にして刷る。上面の外周の面取り 3.0（奥、手前左、親指の下の円弧と直線）
- キーの開口部: 1U の枠から 0.75 外に描き、内側の空間の壁（プレート + 0.7）で切る。R0C3 の奥と R3C3 の左下は壁の円弧に合わせず、
  1U + 0.7 の角の形のまま（`UNCLIPPED_KEYS`）
- 段差 `INNER_TOP` = `B.RIM_Z - Z_OFFSET` = 13.1。ナットのポケット 15.6〜17.4（ナットの下に 2.5）、ネジ穴は手前 18.6、奥 20.0
  （`HOLE_TOP_BACK`。奥のネジは座面が高いため）。ケースのネジは 6 本とも M2 × 10
- ナットのポケットの天井は段付きブリッジ（`NUT_CEILING = "stepped"`）: 天井の 1 層目は穴の幅の帯を空け、2 層目は帯を直角に渡して
  2.4 角を残し、3 層目から丸い穴。層の厚さ 0.2 にそろえる（`_on_layer` の assert）。サポートなしで刷る
- 下端の切り欠き（`wall_cut()`）: 手前はボトムケースの底面の傾斜、y −48（`WALL_CUT_LAND_Y`）から直線で上げ、奥の面（左右の角から奥）は
  水平に z 7.5（`WALL_CUT_BACK_Z` = 面取りの上端 14.0 に一致）

### ボトムケース（`bottom.py`）

- 壁の上端は全周 19.6 で平ら（以前はタブの下だけ柱として残していた）
- 奥の面取り: 高さ 14（`BEVEL_H`）× 奥行き 6。USB-C のくぼみ（上端 12.84）が斜面に収まる。面取りを削る三角形の外への延長は 0.1
  （`BEVEL_OVERRUN`。1.0 だと面取り 14 で奥のネジのボスを削った）
- 奥の 3 本のネジ（トップケースを留める）: ネジ頭は外面より外へはみ出すので、座面を 16.3（`BACK_SEAT_Z` = 面取り + 頭 2.0 + 0.3）に
  上げてトップケースの壁の裏に隠す。ネジ頭の穴（Ø4）は壁より厚いので、床の上に半径 3.2・上端 16.5 の台（`BACK_BOSS_*`）で囲む。
  ネジ頭の穴は外へまっすぐ延ばした U 字（面取りに出る抜けの縁を平行に）。ネジ頭の上のボトムケースの肉 3.3
- 手前の 3 本は座面 14.5（床の上面）のまま

### 底蓋とコントローラー収納部（`bay.py`）

- 電池 EEMB LP502030（250 mAh、`BATTERY` 31 × 21 × 5.3。5.3 は仕様の最大値、公称 5.0。長さ 32 の資料もあるので実測する）
- 底蓋のネジ M2 × 5（`SCREW_LEN`）、ナットの溝 3.85（`NUT_AF`）、`NUT_TIP` 0.75。溝の屋根は、収納部の天井の下面より上の部分だけ

- 天井の最小 0.956（下限 `CEILING_MIN_T` 0.95）、手前のボスの高さ 8.73（屋根の棟 8.175 + 0.5 以上）、USB-C の開け閉めのすき間 0.29

## コントローラー基板（`pcbs/controller`）

- 配線済み、DRC で未配線 0・クリアランス違反なし（残るのは XIAO のフットプリントのシルクの警告 26 件。ユーザーの判断で放置）
- 電源（B.Cu、0.5、ネットクラス Power）: J2 / J3 → U1-19（VBAT）・U1-20（GND）。J2 の GND は H1 の台座の手前の狭い所を通る
  （台座の縁まで約 0.07）
- 信号（F.Cu、0.25、ビアなし）: D0〜D2 は XIAO の下を通って J1 に後ろから、D3〜D6 と D7〜D10 は XIAO の外を回って J1 の手前
  （コネクタの本体の下）から入る
- **J1 のピンの割り当てを変更**: ピン 1〜11 = D6 D5 D4 D3 D2 D1 D0 D10 D9 D8 D7。ケーブルをまっすぐつなぐと
  **D0〜D6 = C0〜C6、D7〜D10 = R0〜R3**（ZMK のオーバーレイに使う）
- 裏面の B.Cu のルールエリア（台座、取り付け穴の中心から半径 3）が 4 つ（H2 だけ「フットプリントを禁止」がオンのまま）
- 裏のシルク: J2 / J3 の極性（− = ピン 1 GND、+ = ピン 2 VBAT）と「BAT L / BAT R」、「optokbd controller / v0.2.0 2026-10」
- 製造前にやること:
  - ティアドロップを付ける（「編集 → ティアドロップを編集」。一度付けて確認し、ユーザーが外した。製造データを作る直前に付ける）
  - 発注は**厚さ 1.0 mm**（KiCad の設定も 1.0。ケースの収納部が 1.0 前提）
  - ガーバーとドリルを書き出して確認。電池のケーブルの極性を実物で確認
- GND のベタはなし（XIAO のアンテナのため）

## ハマりどころ（前回までのメモに追加）

- 時計回りの輪郭の Face は法線が下を向き、`extrude` が下へ押し出される。`dir=(0, 0, 1)` で向きを固定する（トップケースのナットの
  ポケットがこれで 1.8 mm 下にずれていた）
- 押し出し用の断面の折れ目（水平になる所）が外面の最も奥の点にちょうど接すると、長さ 0 の辺ができて 3MF のメッシュが壊れる。
  折れ目は外面の外に置く
- OCC の面取りやフィレットは、接線でつながった辺へ自動で広がる（指定していない親指の下の円弧にも面取りが回っていた）
- 面取りの延長などの「外まで延ばす」逃げは、高さを変えたときに隣の形（ネジのボス）を削っていないか確かめる
- KiCad のプロパティの画面の座標は、補助原点ではなくページの絶対座標。基板の座標 (x, y) は (100 + x, 90 − y)
- KiCad 10 の「配線とビアのクリーンアップ」は「ツール」メニュー。曲がり角の短い配線はクリーンアップでは消えない
- 回路図でラベルを付け替えるとき、電源のラベル（VBAT / GND）を消すとネット名が `Net-(J2-Pin_1)` などになり、ネットクラスが外れる
- `kicad-cli pcb drc --refill-zones` でゾーン（ティアドロップを含む）を塗り直してから DRC できる
- zsh では `"$c:case"` が修飾子として解釈される。`"${c}:case"` と書く
