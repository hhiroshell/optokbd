## 環境と作業の流れ

- ケースの Python プロジェクトは `case/`（uv、build123d 0.13.0）。出力は `case/out/`（`.gitignore` 済み）

  ```bash
  cd case
  uv run python top.py                    # トップケース
  uv run python bottom.py                 # ボトムケース（収納部の加工込み）
  uv run python bay.py [--show]           # 底蓋、テストピース（ネジまわり・ナットの溝・底蓋のまわり）、コントローラー基板の外形
  uv run python gasket.py                 # ガスケット 8 枚（印刷用の配置）
  uv run python matrix_mock.py [--show]   # マトリクス基板のモック、スイッチの穴のテストピース、マトリクス基板の外形。kicad-cli が必要
  uv run python controller_test_board.py  # 印刷用の仮コントローラー基板と XIAO のモック。kicad-cli が必要
  ```

- プレビュー: OCP のスタンドアロンビューア（http://127.0.0.1:3939）を内蔵ブラウザで開いてから送る。
  ビューアは物体の名前ごとに表示・非表示を覚えているので、送るたびに名前を変える。タブが閉じていたら `preview_start` で開き直す。
  断面は、0.5 mm 幅の板で切り出して `ortho=True`、`position` / `target` / `zoom` で視点を決めると見やすい
- 全パーツのプレビュー: トップとボトムケースを半透明（alpha 0.25 / 0.3）にし、底蓋、プレート（DXF の穴あき）、ガスケット、マトリクス基板の
  モックと J1（`matrix_mock.matrix_j1()`）、コントローラー基板・XIAO・USB-C・J1、電池をまとめて送る。プレートの穴は
  `extrude(Face(w), ..., dir=(0, 0, 1))` で向きを固定しないと抜けない
- KiCad 10.0.6。基板はユーザーが KiCad で開いていることが多いので、ファイルを直接書き換えず、スクリプトをスクリプトコンソールで実行してもらう:
  - `scripts/place_matrix.py`: マトリクス基板のスイッチ・ダイオード・J1 の配置
  - `scripts/set_edge_cuts.py`: Edge.Cuts を `case/out/*.json` の外形で描き直す。開いている基板のファイル名で、コントローラー
    （`bay.py` が書き出す）かマトリクス（`matrix_mock.py` が書き出す）かを選ぶ
  - 実行前に、基板ファイルのコピーに同じスクリプトを当てて DRC で確かめておくと安全（`pcbnew.GetBoard` を差し替えて `exec`）
- ユーザーとのやりとりの約束（メモリにも保存済み）: 回答は日本語。モデルを更新したら内蔵ブラウザのビューアに表示する。

## 底蓋とコントローラー収納部（`bay.py`）

### 閉め方
- USB-C の口は収納部の奥の壁の穴に入る（最大 0.6 mm）。底蓋は**手前を下げて傾けた状態で USB-C を穴に差し込み、奥の端を支点に手前を
  持ち上げて閉じ**、四隅を M2 × 6 で留める（まっすぐ押し込むと USB-C が壁に当たる）
- 底蓋の外面より上の点は、開ける向きに回すとどれも手前へ動くので、閉じた位置で奥の壁に当たらなければよい。USB-C は穴の中で上がるので
  `usb_swing_clearance()` で確かめる（すき間 0.28、約 4.0° で抜ける）

### 寸法
- 底蓋: x 25.63〜106.23、手前の端 y −34.5、奥の端は奥の外形から 6.6（`LID_BACK`。チルト 7° で面取りと底面の境目が内側へ寄ったため。
  境目まで 0.91、`bevel_edge_gap()`）
- コントローラー基板: 奥の端は奥の外形から 7.4（`BOARD_BACK`）。基板と XIAO の奥の縁と壁のすき間 0.237（`XIAO_EDGE_PARTS` 1.0 の仮定による）
- USB-C の穴はレセプタクル（8.94 × 3.26 の長円）+ 0.3 の長円、外の窪みは 13 × 7.5 の角 R2.5（`PLUG_R`）。窪みは口の位置で決まり、
  収納部との間の壁は 1.32 mm
- 天井: 下面は底蓋と平行で、底蓋の外面から 8.1（`CEILING_W` = 電池の上面 + 0.5）。いちばん薄い手前の端で 1.54 mm、奥で約 5.2 mm。
  印刷では水平な張り出しなのでサポートが要る。開口（`floor_openings()`、2 つの角丸の長方形をつなげたもの）:
  - J1 のケーブル・マトリクスの J1・J2: x 66.22〜95.23、y は収納部の手前の壁から −13.72 まで（電池の上には開けない）
  - USB-C の上: x 79.76〜90.70、上の開口から奥の壁の先まで
  - `ceiling_clearance()`（天井の下に残る部品とのすき間 ≥ 0.5）、`ceiling_min_thickness()`（≥ 1.0）で確かめる
- J1 のケーブルの溝: 収納部の手前の壁から手前へ、幅 20 × 奥行き 8、底は基板の下面の高さ（`J1_GROOVE_*`）
- 爪を掛ける切り欠き: 底蓋の手前の辺の中央（x 65.93、幅 8）。ボトムケース側は底面から 45° の斜面（壁の面で w 3.0）、底蓋側は手前の端から
  2.0 の溝（手前のリブと電池の枠の前を底蓋の内面まで削る。枠の手前の壁は残す）
- 四隅のネジのナットの溝: 幅 3.95 × 高さ 1.6（M2 ナット 4.0 × 1.6。4.2 × 1.8 では重力で落ちた）。天井は 45° の切妻屋根（高さ 1.975）で、
  サポートなしで刷れる。通し穴は溝の床まで（ネジの先端は屋根の下に入る。ネジの外周での屋根とのすき間 0.175）。
  **高さ方向は層の厚さ単位でしか刷れないので、きつさは幅（横方向）で調整する**
- 電池の枠と電池のモック: 底蓋の座標（x, v）で描いて底蓋に垂直に押し出す（`battery_outline()` の Y は v）
- J2 / J3 の足の凹み: 両方に、深さ 1.0（`BATTERY_PINS`）
- 電池のケーブルのガイド（`cable_guides()`）: キノコ形の柱 2 本。柱 Ø3.0（まっすぐな部分 1.0）、傘 Ø5.0、傘の下面は 45° の円すい、縁 0.3、
  上面は底蓋の内面から 2.3（基板の上面の 0.2 下）。基板の左の 2 つの切り欠き（左手ではボスがない角）の中、基板の座標で
  (−17.3, −3.5) と (−17.3, −25.4)。柱と電池の枠の間 1.5、傘と枠 0.5、傘と切り欠きの縁 1.0。手前の傘は爪の溝の上に出る
  （爪より高いので当たらない。底蓋には溝を掘った後でガイドを足す）。`check_cable_guides()` で確かめる
- ケーブルの通り道: 電池の右上から横へ出て、電池の枠の右の外面に沿って奥から手前へ（基板の下、高さ 1.5）、手前の柱で折り返して J2 の
  プラグへ。右手の底蓋は鏡像なので、基板の右の切り欠きと J3 に合う

## ハマりどころ（前回までのメモに追加）

- KiCad 10 の裏面のフットプリント: 裏返した直後の角度は 180°。`SetOrientationDegrees(r)` は「上下反転 + 回転」として効くので、
  表の向きを左右に裏返した形にしたいときは `r + 180` にする
- `bay` と `matrix_mock` は互いを使う。`bay.floor_openings()` は関数の中で `matrix_mock` を読み込み、`matrix_mock` は `bay` を
  `__main__` の中で読み込む（先頭で読み込むと循環する）
- 寸法を探るときは `python -O` で assert を外して数値だけ出せる。作業用のコピーで試すときは、コピー先で
  `uv run --project <case のパス> python ...` を実行する（`sys.path` に `.` を足しても、元のディレクトリの物を読むことがある）
- ezdxf で DXF を保存すると、ファイル全体が書き直されて差分が大きくなる。中身の比較はエンティティ単位で行う
- 3D プリンタは高さ方向を層の厚さ単位でしか刷れない。0.05 mm 単位のきつさの調整は横方向（x、y）で行う
- 2D の角丸の判定は、長方形を丸め半径だけ縮めて調べると辺まで縮んでしまう。角の部分だけを円で判定する（`ceiling_clearance()`）
