## 環境と作業の流れ

- ケースの Python プロジェクトは `case/`（uv、build123d 0.13.0）。出力は `case/out/`（`.gitignore` 済み）

  ```bash
  cd case
  uv run python top.py                    # トップケース、トップケースのナットのテストピース（top-nut-test-l）
  uv run python bottom.py                 # ボトムケース
  uv run python bay.py [--show]           # 底蓋、収納部の天井（bay-ceiling-l）、テストピース、コントローラー基板の外形
  uv run python gasket.py                 # ガスケット 8 枚
  uv run python plate.py                  # プレートのモック（DXF から）と、発注用のプレートの外形（out/plate-outline.json）
  uv run python matrix_mock.py [--show]   # マトリクス基板のモック、外形（左右の JSON）。kicad-cli が必要
  uv run python controller_test_board.py  # 印刷用の仮コントローラー基板と XIAO のモック
  ```

- 基板まわりのスクリプト（`scripts/`）:

  | スクリプト | 実行する場所 | 内容 |
  |---|---|---|
  | `place_matrix.py` | KiCad のスクリプトコンソール | マトリクス基板のスイッチ・ダイオード・J1 の配置。基板のファイル名で左右を判定 |
  | `place_socket_vias.py` | 同上 | ソケットの列のパッドの横（固定用の穴を結ぶ線の上）にビアと短い線。何度実行してもよい |
  | `set_edge_cuts.py` | 同上 | Edge.Cuts を `case/out/*.json` で描き直す（controller、matrix-left、matrix-right） |
  | `add_matrix_silk.py` | 同上 | マトリクス基板の裏に名前と版（`optokbd matrix L/R`） |
  | `add_silk_labels.py` | 同上 | コントローラー基板の裏のシルク |
  | `add_lcsc_fields.py` | ターミナル（`python3`）。回路図エディタは閉じておく | 回路図の部品に LCSC の番号（フットプリントで決める）。そのあと PCB エディタで F8 |
  | `export_jlc_assembly.py` | ターミナル（`/usr/bin/python3`） | マトリクス基板の BOM / CPL を `pcbs/<基板>/jlcpcb/` に |
  | `export_gerbers.py` | 同上 | 4 枚のガーバー / ドリルと zip を `pcbs/<基板>/jlcpcb/` に。一時コピーでゾーンを塗り直し、DRC とティアドロップを確かめてから書き出す |
  | `make_plate_board.py` | 同上 | `pcbs/plate`（発注用のプレートの基板）を `case/out/plate-outline.json` から作り直す |

- KiCad のスクリプトコンソールは、**1 回の入力で 1 つの文しか受け付けない**（複数行を貼るとエラー）。スクリプトはファイルにして
  `exec(open('/home/hhiroshell/src/github.com/hhiroshell/optokbd/scripts/<名前>.py').read())` の 1 行で実行してもらう
- 基板はユーザーが KiCad で開いていることが多い。ファイルを直接書き換えず、スクリプトをコンソールで実行してもらう。実行前に、
  基板のコピーに当てて確かめる（`/usr/bin/python3` で `pcbnew.LoadBoard` し、`pcbnew.GetBoard` と `pcbnew.Refresh` を差し替えて
  `exec`、`kicad-cli pcb drc` で確認）。回路図を書き換えるときは、ロックファイル（`~*.kicad_sch.lck`）がないことを確かめる
- プレビュー: OCP のスタンドアロンビューア（http://127.0.0.1:3939）を内蔵ブラウザで開いてから送る。送るたびに名前を変える
  （`-v26` まで使った）。Remote Control でモバイルからも見ているので、SVG や PNG も `SendUserFile` で送る
- 全パーツの分解図（組立説明書ふう）: 各部品を組み付けた位置から z だけずらし、下から 底蓋 → コントローラー基板・XIAO・USB-C・
  電池 → ボトムケース → マトリクス基板 → プレートとガスケット → トップケース の順に、すき間 20 mm で積む。ガスケット・プレート・
  トップケースは z に `L.Z_OFFSET` を足す（組み付けた位置）。スクリプトはリポジトリに入れていない
- ユーザーとのやりとりの約束（メモリにも保存済み）: 回答は日本語。モデルを更新したら内蔵ブラウザのビューアに表示する。
  コミットメッセージは英語、コミットや push は頼まれたときだけ。ネジは M2 の六角穴付きボルト + ナット（インサートは使わない）。
  コミットは内容ごとに分ける

## ケース

- 高さ（ボトムケースの z）は前回のメモのとおり（トップケースの上面 29.1、プレート 22.0〜23.6、壁の上端 19.6、マトリクス基板
  17.0〜18.6、床の上面 14.5、奥の面取りの上端 14.0）
- 印刷: エレファントフット（1 層目のはみ出し）は、Bambu Studio のエレファントフット補正を大きくして対処している。底蓋だけは
  モデルでも面取りした

### ボトムケース（`bottom.py`）

- 奥の面取りの断面は、上下の端を通る円弧で、中央で外へ `BEVEL_BULGE` = 0.2 mm ふくらむ（印刷すると底から奥へ一度内側へ凹む
  ように反ったため。最初 0.3、ユーザーの判断で 0.2）。上の端（トップケースの壁の下端が合う稜線）は動かない。斜面の面は
  円すいではなくトーラスになったので、面取りの面は `bevel_face()` で探す
- 収納部は床の上面まで貫通（天井は別の部品）。下の「収納部の天井」

### 底蓋と収納部（`bay.py`）

- **収納部の天井は別の部品**（`ceiling()`、出力 `bay-ceiling-l`）。ボトムケースに上から載せて接着する
  - 理由: 一体だと印刷の向きで水平な広い張り出しになり、その層で外形がゆがんで奥の面取りに筋が出た
  - ボトムケース: 収納部の壁から `CEILING_LEDGE` 1.5 mm 外までを、天井の下面の高さまで削って受けにする（印刷の向きで上を向く面）
  - USB-C の穴の上は受けを作らない（`CEILING_USB_KEEP`: 天井の USB-C の上の開口の左右 1.5 mm 外まで。段を作ると穴の上が
    壊れやすかった）。`usb_ledge_keep()`
  - 四隅のボスは、天井の下面より上で受けの段を埋めて外の壁につなげる（下まで広げると奥のボスが面取りから外へ出る）
  - 天井の部品: 受けの縁の壁と四隅のボスから `CEILING_FIT` 0.2 mm 離す。厚さは手前 0.98 mm、奥で約 5 mm。J1 のケーブルの開口と
    USB-C の上の開口がつながって手前から奥まで抜けるので、**2 枚に分かれる**（左 約 56 × 34、右 約 17 × 33。ユーザー了承済み）。
    下面を下にして刷る（`ceiling_print()`）
  - 奥の真ん中のネジ頭の穴と受けの間の壁は 2.10 mm（`back_screw_ledge_gap()` の assert は 1.5 以上）
- 電池のケーブルのガイド（キノコ）: 柱 Ø2.0、屋根 Ø4.0（`POST_D`、`CAP_D`。502030 の電池はリード線が長く、柱 3.0・屋根 5.0 では
  巻ききれなかった）。屋根の下は 45° の円すい（サポートなし）。屋根の下のすき間は柱の根元で 1.0、縁で 2.0。位置は x −17.3
- 底蓋の外面の縁（外周とネジ頭の座ぐりの口）に 45° の面取り `LID_BED_CHAMFER` 0.4 mm（外面を下にして刷るので、エレファント
  フットで収納部の開口とのすき間 0.2 が減らないように）
- 底蓋の閉め方: 奥から入れる（手前を下げて傾け、USB-C を奥の壁の穴に差し込み、奥の端を支点に手前を持ち上げて閉じる）。
  四隅を M2 × 5 で、ボスに横から差したナットに留める

### プレート（`plate.py`、`pcbs/plate`）

- 発注用のプレートは、左手の DXF（`plate/plate_left.dxf`。外形とタブ、スイッチ穴）から作る。**右手は同じ板を裏返して使う**（銅も
  部品もないので、裏返すと x を反転した右手の形になる）。`plate/plate_right.dxf` は外形とタブのない古いもので、使っていない
- 穴の中心は、左手のマトリクス基板（そのまま）と右手のマトリクス基板（裏返し）のスイッチの中心と、ずれ 0.0000 mm で一致
- 穴と穴の間は最小 5.04 mm、穴と外形の間は最小 2.36 mm。大きさ 133.35 × 91.44 mm
- 裏面のシルク（名前と版）は、奥の左のタブの根元（どちらの面を上にしてもトップケースに隠れる所）
- Edge.Cuts の線は 0.15 mm（0.05 では JLCPCB のプレビューで穴の辺が消えて見えた）

## マトリクス基板（`pcbs/matrix-left`、`pcbs/matrix-right`）

- 配置: スイッチ（Kailh MX ホットスワップ、裏面のソケット）、ダイオード 1N4148W SOD-123（裏）、J1 SM11B-SRSS-TB（裏）。
  R1〜R3 のキーは上下を反転。ダイオードはキーの中心から (7.3, 2.6)・−90°（ソケットのパッド 2 の真下。R0 は右下、R1 から下は
  左上）。右手はキーの位置と回転を x で反転するが、フットプリントは鏡像にしない（ダイオードのオフセットも反転しない）
- 配線: 列は表（F.Cu）、行と J1 からの線は裏（B.Cu、R0 と R1 の間の帯）、R2・R3 は表で J1 まで上げる。ビアは 36 個（ソケットの横
  25、列への乗り換え 7、R2・R3 に 4）。ソケットからダイオードへの線は 4.7〜6.6 mm。右手はアノードの線を円弧で曲げている
- **J1 のピンの割り当て**（ピン 11 → 1）:
  - 左手: C3 C2 C1 C0 R3 R2 R1 R0 C4 C6 C5
  - 右手: C5 C6 R3 R2 R1 R0 C4 C0 C1 C2 C3
- 裏面のシルク `optokbd matrix L/R` / `v0.2.0 2026-10`（R2 の C0・C1 の手前）。ティアドロップあり（左 222、右 219）
- 部品に LCSC の番号のフィールドあり（回路図と基板）
- DRC: 未配線 0、エラーなし。残るのはシルクの警告と、回路図との照合の `net_conflict` 50 件（誤検出。ネットリストと全パッドの
  ネットが一致することを確かめた。kicad-cli がこのプロジェクトの回路図を照合するときの癖）

## コントローラー基板（`pcbs/controller`）

- 配線の角を円弧に（線幅は同じ）。ティアドロップ 27 個。U1-3（D2）と U1-20（GND）はティアドロップを外し、パッドの設定もオフ
  （保存されていた古い塗りで、隣のパッドに 0.001 / 0.09 mm まで近づいていたため。塗り直せば問題なかったが、外したままにした）
- 厚さ 1.0 mm。電池のコネクタの極性は、実物の電池で確かめた（シルクのとおりで OK）
- DRC: 未配線 0、エラーなし。取り付け穴 H1〜H4 の「回路図にない部品」の警告 4 件は無害

## JLCPCB への発注（2026-10-24）

- ファイル（`jlcpcb/` は `.gitignore` 済み。スクリプトで作り直せる）: 各基板の `pcbs/<基板>/jlcpcb/<基板>-gerbers.zip`、
  マトリクス基板は同じフォルダの `-bom.csv` と `-cpl.csv`
- 基板の設定: FR-4 TG135、2 層、ビア処理「レジストカバー」、PCB 上のマーク「マーク除去」（今の注文画面には位置の指定はない）。
  プレートには銅がないので、表面処理やビア処理は何でもよい
- 部品実装（マトリクス基板）: Economic、裏面（Bottom Side）
  - ソケット **C41430893**（HanElectricity CPG151101S11-16。Kailh の C2803348 と C5184526 は在庫 0 で Standard のみ）。
    データシートの推奨パッド配置は穴 Ø3.00、間隔 6.35 × 2.54 で、今のフットプリントと同じ
  - ダイオード **C81598**（Basic）
  - J1 **C515956**（JST。2026-10-23 の在庫は 12 個）
  - **CPL の回転**: 表の部品は KiCad の向き、裏の部品は `180 − KiCad の向き`。ソケットはフットプリントが表でパッドが裏なので
    Bottom として扱い、中心はパッドの範囲の中心（スイッチの中心ではない）。EasyEDA の部品のフットプリントで、全部品のパッドと穴が
    0.1 mm 以内で重なることを確かめ、JLCPCB のプレビューでもソケット・ダイオード・J1 の向きが正しいことを確かめた
  - 「Confirm Production File」をオンにすることを勧めた（オンにしたかは未確認）。プレビューと実際の実装の向きが食い違ったという
    報告（kicad-jlcpcb-tools の issue #636）があるため
- 部品の向きを確かめるときに使える、EasyEDA のフットプリントの API:
  `https://easyeda.com/api/products/<LCSC 番号>/components?version=6.4.19.5`（`packageDetail.dataStr.shape` の `PAD~` と
  `HOLE~`。単位は 10 mil = 0.254 mm、y は下が正、原点は `head.x / head.y`）

## ファームウェア（ZMK）のための情報

- ダイオードの向き: カソードが行の側（col2row）
- コントローラー基板の J1 はピン 1〜11 = D6 D5 D4 D3 D2 D1 D0 D10 D9 D8 D7。マトリクス基板のピン k がコントローラーのピン 12 − k に
  つながるとき（今の前提。ケーブルの向きで変わる）、XIAO のピンは:

  | | C0〜C6 | R0〜R3 |
  |---|---|---|
  | 左手 | D3 D4 D5 D6 D9 D7 D8 | D10 D0 D1 D2 |
  | 右手 | D10 D9 D8 D7 D0 D6 D5 | D1 D2 D3 D4 |

- 右手の C0 は外側（小指の側）。KLE の並び（右手は内側が列 0）とは matrix-transform で合わせる
- ケーブルが逆向き（ピン k ↔ ピン k）なら、上の表は作り直す（基板は変えなくてよい）

## ハマりどころ（前回までのメモに追加）

- **KiCad の DRC は、ティアドロップが別のネットのパッドに近づきすぎていても出さないことがある**。原因はファイルに保存された
  ゾーンの塗りが古いこと（配線を変えたあと塗り直さずに保存した）。塗り直すとクリアランスを守った形になる。KiCad で配線を変えたら
  B キー（すべてのゾーンを塗りつぶし）を押してから保存する。`kicad-cli pcb export gerbers --check-zones` は「必要なら」塗り直す
  だけなので、`export_gerbers.py` は一時コピーで必ず塗り直してから確かめて書き出す
- 円弧の配線で、始点と終点がほぼ重なり途中の点だけ離れたもの（ドラッグで直したときにできる）は、DRC ではほぼ一周の大きな円として
  扱われ、離れた穴や基板の縁とのクリアランス違反になる。範囲（バウンディングボックス）が長さよりずっと大きい円弧を探し、同じ
  2 点を結ぶ直線に置き換える
- ホットスワップソケットのフットプリントは、パッドの形が基準点から 0.45 mm ずれて定義されている。パッドの中心は `ShapePos()` で取る
- pcbnew の Python（KiCad の外）: 部品を順に処理しながら `board.Remove()` すると SWIG のエラーになることがある。消すものを先に
  集めてから消す。Python のスクリプトをコンソールで `exec` すると変数がコンソールに残るので、`b` などの短い名前を使わない。
  保存のあとに別の処理をすると落ちることがあるので、確かめは別のプロセスで読み直して行う
- `add_lcsc_fields.py` のように回路図のファイルを直接書き換えるときは、回路図エディタが閉じていること（ロックファイルがないこと）を
  確かめる。PCB エディタを閉じても、回路図エディタが開いたままのことがある
- 作業ツリーで `git stash` を使うと、KiCad で開いているファイルも一時的に書き換わる。KiCad が開いている間は使わない
- KiCad の SVG には検索用の見えない `<text>` が入っていて、ImageMagick はそれも描く（文字が二重に見える）。PNG にする前に
  `<text>…</text>` を消す
- JLCPCB の CPL: 裏面の部品の回転は `180 − KiCad の向き`。KiCad の向きのままだと 180° ずれて見える
- JLCPCB のプレビューは、Edge.Cuts の 0.05 mm の線を消したり途切れさせたりする。発注するプレートは 0.15 mm にした
- build123d: 円弧の断面を回転させた面は `GeomType.TORUS`（円すいではない）
